# 《第二大脑》Logseq 2.0 DB 逐章学习指南 V2.0

> **教材**：涂子沛，《第二大脑：脑机协作如何改变个人发展和家族传承》（2023），按用户上传的 166 页 PDF 页序引用。  
> **软件基准**：Logseq 2.0.2 Beta（DB graph；2026-10-07 发布）。**核查时间**：2026-10-08。  
> **原则**：以原书的学习顺序、示例意图和知识管理方法为主，以新版 Logseq 官方可核实的操作方式为主。  
> **不包含**：Obsidian 替换教程、Tiago Forte 的 CODE / PARA、未经确认的插件功能，以及将原书设想误报成当前软件能力。  
> **可验证性**：菜单/机制参考官方文档、2.0.2 Release Notes；**尚未在本机 GUI 完成逐项实测**。因此每节要求读者记录实际验收结果。

## 0. 使用前必读：软件版本、开放性与安全边界

### 0.1 选择哪个 Logseq？

| | Logseq 2.0 DB（**本指南主线**） | Logseq OG（原书环境／对照） |
|---|---|---|
| 官方仓库 | https://github.com/logseq/logseq | https://github.com/logseq/og |
| 已核实 Release | 2.0.2 Beta，2026-10-07 | 1.0.0，2026-04-15 |
| 数据真源 | 本地 SQLite 数据库（DB 图谱） | 本地 Markdown 文件（文件图谱） |
| 页面与块 | 统一为 Node | Page + Block 模型 |
| 引用机制 | 页面/块统一使用 `[[...]]` 的 Node reference | 页面 `[[...]]`，块 `((UUID))` |
| 查询 | `/Query` 构建器；`/Advanced Query` | 旧 `{{query ...}}` 宏、旧高级 Query |
| 核心白板 | 官方变更说明明确：DB 内置 Whiteboard 被移除 | 原书使用的是旧版相关能力 |
| 数据风险 | 仍为 Beta，不宜直接使用重要生产知识库 | 传统文件型流程；不代表没有数据风险 |

**重要判断**：新版本不是“OG 更高版本号”，而是不同的数据模型与交互模式。两者都是开源软件产品线；DB 的付费/邀请制协作同步不能与本地开源编辑能力混为一谈。

### 0.2 环境设置（建议 15 分钟）

1. 从 [官方 2.0.2 Release](https://github.com/logseq/logseq/releases/tag/2.0.2) 下载与你的操作系统匹配的 **Logseq DB** 安装包；不要选择 Nightly 作为第一轮学习基准。
2. 安装并打开 Logseq；新建**独立的本地 DB graph**，名称建议 `SecondBrain-Book-DB-Lab`。若弹出同步选项，第一轮选本地、不开通协作同步。
3. 在图谱创建一个页面 `[[学习导航]]`，写上“这是实验图谱，不包含生产数据”。
4. 依官方页面进入 **Settings > Keymap** 核对快捷键；本指南以 Mac 快捷键为例，Windows/Linux 某些快捷键不同。
5. 创建一条测试块并退出、重启，确认文本存在。找到图谱导出菜单：右上角 `...` → `Export graph`。后续随学习阶段定期导出 **SQLite DB + assets**。
6. 打开《练习验收表.md》，记录 `OS`、`Logseq 版本`、`图谱名称`、`开始时间`。每完成一节，登记“通过/部分通过/未通过”和截图、版本差异。

> **Beta 数据边界**：不要连接正在使用的个人图谱，不存储密码、证件、个人健康数据；DB 不能把目录中的 `.md` 视为可直接编辑的图谱真源。练习包是文本教程与输入素材，**不是可双击使用的原生 DB 图谱备份**。

### 0.3 这次采用的三种结果标签

- **N 原生功能**：已从新版官方文档或 Release Notes 核实存在，例如 Node、标签、任务、查询构建器。
- **A 适配实现**：学习目标一致，但需要换交互，例如原书 `((UUID))` 改成新版 Node 引用。
- **L 限制／独立演练**：官方资料明确已移除、没有确认存在，或属于作者的技术愿景。**不伪造等价按钮**。

使用规则：每一项只按“原书对应 → 新版做法 → 预期结果 → 验收 → 差异”完成，不需要同时安装第三方插件。

# 第一章 为什么需要第二大脑（原书 PDF p.7–25）

## 1.1 原书主旨【原书】

作者将第二大脑描述为属于个人的数字记忆体。它不是公共互联网的替代搜索引擎，而是应同时支持**保存、检索、关联和辅助思考**。第二大脑并不等于软件安装完成。原书 p.16–24 解释外部记忆与思考的关系，并列举了当时常用的 Logseq、Obsidian 等工具。

## 1.2 练习 01：自己的第一条可检索记录【N】

**步骤**：
1. 打开今天的 `Journals`；按一个新 Block 输入：`今天的一项观察：当资料分散在多个地方时，我会重复寻找。`
2. 新建子块：`未来用途：给一个具体项目提供线索。`
3. 使用全局搜索寻找关键词“重复寻找”；打开命中的块。
4. 返回 `[[学习导航]]`，放入对当日 Journal 的引用或自然语言日期链接，测试可回到原记录。

**验收**：能保存、检索并回到同一条记录；指出“记录事实”与“得出判断”不是同一回事。

# 第二章 构建数字记忆体（原书 PDF p.26–76）

## 2.1 块：第二大脑的神经元（p.26–33，图 2-2 至 2-5）【A】

**原书**：块可以形成父块、子块、孙块；Logseq OG 通过块 UUID 与 `((UUID))`、嵌入式引用避免重复复制。

**DB 版关键变化**：页面和块统一称为 **Node**。Node 统一用 `[[...]]` 引用；**不要继续手打 `((UUID))` 或 `{{embed ((UUID))}}` 当作新版标准操作**。嵌入改用 `/Node embed`。Node 带创建/更新时间戳。

**练习 02：层级与引用**：
1. 在 `[[块与引用实验]]` 页面建一个父块 `长期阅读是主题`；在它下方建子块 `记录比记住更可靠`，子块下再建一层“我自己的例子”。通过 Tab/Shift+Tab 或块菜单调整缩进。
2. 将光标放在子块，使用编辑器/块菜单的引用入口（或从搜索选取已有 Node）复制/插入指向它的 **Node reference**；不要假定页面链接和块链接需要不同括号。
3. 在 `[[主题反射区实验]]` 另建一个块，输入 `[[` 并搜索定位刚才的 Node，插入引用。点击链接，确认跳转/聚焦到原 Node。
4. 新建一个块，输入 `/Node embed`，选择来源块；回到源块更改一句话，检查嵌入是否随之更新。
5. 缩进、展开/折叠、将一个块置于侧边栏，观察同一身份的引用和视图。

**验收**：有父-子-孙三级；可以从两处跳转回同一 Node；嵌入与复制的差异可观察。

**差异**：原书对 `block/uuid`、`block/left`、`db/id` 的屏幕截图属于 OG/旧数据模式，不要求在 2.0 DB 中逐字段复现；新版属性/底层字段不能按旧模式查询。

## 2.2 标签：为块建立人工突触（p.34–42，图 2-8 至 2-12）【A/N】

**原书**：`[[湖泊]]`、`#地理`、块层级和反向引用使信息具有多重归属。书中还讨论父子块标签继承。

**DB 版变化**：`#标签` 不只是文字引用，还可以变成带**属性模式（Tag Properties）**的类型／类。输入 `#地理` 后按 Enter，通常创建/应用标签并让其显示在块右侧；需要旧式行内标签则使用 `Cmd-Enter`（Mac；以本机键位为准）。标签 `Extends` 是**标签间继承属性**，不等于旧书所述的块父子标签继承，两个概念必须分开验证。

**练习 03：半岛—湖泊**：
1. 创建 `[[半岛]]`、`[[湖泊]]`、`[[地理]]` 三个页面。
2. 在“半岛”新建一条块：`半岛与湖泊都能在地理主题中讨论。`，用 `[[湖泊]]` 建立页面引用，再为这个块附上 `#地理` 标签。
3. 打开“湖泊”页面，查看 **Linked References**；返回“半岛”，观察页面关联。
4. 为同一块再附上 `#自然`，打开两个 Tag 页面，查看各自的 Tagged Nodes 视图。
5. 建一个父块并给它添加 `#自然`；在下方建不带标签的子块。分别查看父块和子块的**实际**标签/视图，记录与原书“继承”行为是否相同。**不要预设会等价继承。**

**练习 04：标签属性（新增功能，不是原书旧操作）**：
1. 创建 `#阅读笔记`，在标签配置页设置 `Tag Properties`：`作者`（Text）、`重要程度`（Number）。
2. 在一个块上应用 `#阅读笔记`，检查是否出现可编辑的两个属性。
3. 可选：创建 `#研究阅读`，设置它的 `Extends` 指向 `#阅读笔记`；验证继承的**属性模式**。

**验收**：能看到反向引用、双重标签聚合与 Tag Properties；能解释“同一条记录属于多个主题”不等于“多个相同内容的副本”。

## 2.3 页：第二大脑的反射区（p.43–56，图 2-14 至 2-20）【A】

**原书**：主题页包含人工组织的主反射区、系统聚合的 **Linked References** 与 **Unlinked References**。作者主张把有价值的弱关联笔记组织到主题正文里，而不是停留在引用列表。

**练习 05：历史主题页**：
1. 创建页面 `[[历史]]`，添加一级内容“我现在如何理解历史？”及两个子块“经验”“证据”。这是你人工编辑的主反射区。
2. 去今天 Journal 写一条包含 `[[历史]]` 的块；回到“历史”，检查 Linked References。
3. 另写一条**纯文本**提及“历史”但不建引用的块，检查页面 Unlinked References。若无结果，请标记为“界面/索引待核对”，不要手工补造所谓系统列表。
4. 将一条相关记录用 `/Node embed` 或 Node reference 加入页面正文下的合适位置，再解释为何收录。
5. 查看引用区域能否切换 `Table/List/Gallery` 和设置筛选；视图是新版功能，不是原书“三分区”的完全同构。

**验收**：清楚区分人写的主题结构与系统产生的关联视图；至少完成一条引用聚合到正文的操作。

## 2.4 构建神经中枢和大脑皮层（p.57–65，图 2-21）【A/N】

**原书**：多个主题页面逐渐构成集群（神经中枢）；不主张先规划一个僵硬完整目录。

**练习 06：导航页和 Library**：
1. 创建 `[[知识中枢]]`，写两个块：“社会与人生：`[[历史]]`、`[[友谊]]`”；“自然与观察：`[[半岛]]`、`[[湖泊]]`”。
2. 使用页面链接导航；新增一个 `[[记忆]]` 页面并归入适当集群。
3. 打开新版 **Library**，比较“名称空间组织页面”与“标签跨页聚合”的差异：Library 更接近页面层级，标签更适合具有共同属性的类型。
4. 不强求把“知识中枢”全变为标签或全部变为文件夹；本练习是原书的主题聚合意图。

**验收**：一个集群能导航至 ≥4 个页面；至少有一条跨集群引用；能解释两种组织方式的用途。

## 2.5 用四个大类分拣一生的信息（p.66–67）【A】

**书中的四类（严格保留原文分类逻辑）**：

| 原书类别 | 本次 DB 图谱实现建议 | 判定原则 |
|---|---|---|
| 各领域知识 | 主题页面及导航，必要时用标签 | 长期可持续维护 |
| 需要完成的项目 | 项目主页／`#项目` 标签 / 任务关联 | 有完成条件 |
| 日志 | `#Journal` 页面（Journals） | 与日期相关／尚不确定归属 |
| 备忘信息 | `[[备忘信息]]` 页面或指定标签 | 简单备查，无需复杂整理 |

**练习 07**：每类各创建一条样例。在 `[[项目示例]]` 页面汇总 3 个相关来源；将一条尚不能归类的观察放入 Journal；一周后决定是否关联项目、领域或保留日记。

**特别强调**：本书四类不是 Forte 的 PARA。原书描述过用备忘录保管密码或证件的做法，但新版实践中**不要明文存放密码、密钥、身份证件**。

## 2.6 使用全新的日记模式（p.68–76，图 2-29 至 2-33）【A/N】

**原书**：Journal 与目标、任务、日期、模板、项目联系；旧版出现 NOW/LATER/DONE 任务和 `+1d` 之类重复记录。

**DB 版变化**：任务是 `#Task` 的 Block，包含 `Status`、`Priority`、`Deadline`、`Scheduled`。内置状态包括 Backlog / Todo / Doing / In Review / Done / Canceled；重复任务通过截止/计划日期的 **Repeat task** 设置，完成后系统更新下一次任务日期并重置状态。这不等于旧宏自动提醒，更不等于操作系统弹窗推送。

**练习 08：今天的项目任务**：
1. 打开 Journal，创建块 `整理第二大脑第二章的演示`。
2. 在块内执行 `/todo`（或为块添加 `#Task`）；快捷键 `p s` 可以设置 Status；选择 `Todo`。
3. 执行 `/Deadline`，设置明天；使用 `p p` 设置 Priority（可选）。
4. 将本块与 `[[项目示例]]` 建立引用；在 `#Task` 页面以 Table View 检查其状态、日期和对应内容。
5. 变更 Status：Todo → Doing → Done，观察状态历史显示。

**练习 09：重复任务与模板**：
1. 新建一个无关紧要的测试任务“每天查看学习记录”。为 Deadline 或 Scheduled 打开日期弹窗，勾选 `Repeat task`，设置每日。
2. 变更为 `Done`，检查该测试任务的状态和日期是否按当前版本行为更新；不要在生产数据里进行重复测试。
3. 新建一个块 `每日学习复盘` 并加 `#Template`，添加三个子块 `收获`、`卡点`、`下一步`。
4. 在新 Journal 中执行 `/Template`，选择该模板，验证三个子块被复制过来。可选将模板配置为 `Apply template to tags = #Journal`，但仅对测试图谱启用。

**验收**：一个 Task 在 `#Task` 页面可找到；状态和日期可编辑；重复规则有可见效果；模板可以插入。记录任何与书中图 2-29、2-30 的行为差异。

# 第三章 创建高级的思考特质（原书 PDF p.77–118）

## 3.1 构建网状立体结构（p.77–86，图 3-3 至 3-5）【N】

**原书**：同一条记录可同时关联内容、修辞、经历、主题等多个维度。

**练习 10**：在 Journal 新增块 `我用“桥梁”比喻知识之间的联系，帮助我理解记忆与交流。`；分别加 `#记忆`、`#比喻`、`#交流`；在子块解释为什么是这三个维度。检查三个标签页面是否汇聚同一个 Node。

**验收**：一个节点拥有 3 个可解释的关系，且不是复制三份文本。

## 3.2 洞察、发现新的联系（p.87–99，图 3-6、3-13）【N/L】

**已核实新版情况**：2026 年 Logseq 2.0 DB 的 **Graph View V2** 已重做；但官方变更文档指出，DB 原生 **Whiteboard（白板）已移除**。这两者是不同功能，不可混淆。

**练习 11：图谱关系**：
1. 创建并关联 `[[孤独]] → [[勇气]] → [[记忆]]` 三个主题（箭头仅作文字说明，真实关系通过页面引用建立）。
2. 在 Logseq 菜单/搜索命令查找 `Graph View` 或图谱入口（具体 UI 根据 2.0.2 的本机版本核对）。
3. 显示图谱，找出“孤独”与“记忆”的可解释连接路径；逐条点击核对来源内容。
4. 参考原书图 3-13，**用一张文本关系表**假设移除中间节点，再人工判断其他路径是否仍成立。不要因为图谱可以打开，就假定有“一键移除节点并自动求最短路径”的内置功能。

**练习 12：替代原书 Whiteboard**：

在页面 `[[关系分析实验]]` 内手写如下关系表。原书的白板视觉排布不作为 DB 原生功能验收项。

| 源节点 | 关系解释 | 目标节点 | 原始依据 |
|---|---|---|---|
| 孤独 | 某条记录讨论面对未知时的勇气 | 勇气 | 链到来源 Node |
| 勇气 | 某条经历影响对记忆的理解 | 记忆 | 链到来源 Node |

**验收**：图谱中能查到真实节点/关系；至少两条关系有内容依据。白板项标记 L，除非后来安装**经核实支持 DB 的插件**并另行测试。

## 3.3 脑机协作催化新的创意（p.100–105）【A】

**原书**：信息外化、集中比较、发现联系，可辅助创意产生；不意味着软件自动做出了有效结论。

**练习 13**：打开 `[[历史]]`、`[[记忆]]`、`[[项目示例]]` 三处的相关记录；把三条来源用 Node 引用放到 `[[创意实验]]`；手写一个“由这三条信息共同启发的新想法”，并注明“假设/待验证”。

**验收**：一条新思考能回溯三条源 Node，且明确区分原文、改写和个人推断。

## 3.4 使用 Query 和搜索的技巧（p.106–111，图 3-15 至 3-18）【A/N】

**原书的三个核心问题**：
1. 哪些块同时带有 `#比喻` 与 `#孤独`？
2. 哪些块带有 `#比喻`，同时文本包含“孤独”？
3. 哪些块同时在正文包含“比喻”“孤独”？

**新版本不能直接复制书中 `{{query (and ...)}}`**。新版应使用 `/Query` 图形构建器，为当前 Query 增加过滤条件，结果通过 **List/Table/Gallery View** 展示。高级查询改用 `/Advanced Query`；旧查询里的某些字段改名，不建议在初学阶段直接写 Datalog。

**练习 14：三次筛选**：
1. 在 `[[查询实验台]]` 新建 Query 节点，执行 `/Query`，按界面新增 `Tag = 比喻` 和 `Tag = 孤独`，组合为“全部满足/AND”。若显示的是节点属性/标签筛选，根据本地 UI 核对字段名称。
2. 再建立一个 Query：`Tag = 比喻` + 文本关键词“孤独”。若 Query Builder 当前版本未提供全文包含条件，则先用全局 Search 复现文本部分，并将严格等效结果标注“部分通过”，**不得把搜索结果冒充为完整 Query 结果**。
3. 第三个目标用全局 Search 定位同时含两个词的原文；若界面能建相应 Query 则记录 Query 配置。检查与“两个 Tag 相交”的结果为何不同。
4. 在 `#Task` 列表或 Query Builder 新建过滤 `Status != Done`（以界面运算符为准）；再使用日期范围筛选本周已安排的任务。与“实际完成时间”不同，不能凭 Journal 日期推定完成日期。
5. 尝试 `List View` 和 `Table View`，将 `Status` / `Deadline` 列显示出来，保存 Query。

**验收**：一个多条件 Query 能正确返回测试记录；能解释标签条件、正文检索、任务日期是三种不同维度。记录 Query Builder 实际可用的条件名称。

**进阶提示**：旧 `:block/content` 改为 `:block/title`、`:block/left` 被替换为 `:block/order`、任务字段改为 `:logseq.property/status` 等。只作为新版 schema 边界理解，不提供未经环境实测的可执行高级 Query 语句。

## 3.5 改写、化用和互文：创建新的“脑细胞”（p.112–118）【N】

**原书**：不要让知识库沦为摘录剪贴本。保存源信息，再用自己的语言改写，并将改写和关联不断修订。

**练习 15**：新建 `[[改写实验]]`，使用 4 个子块：`原始出处（短摘录或链接）`、`我自己的改写`、`与哪些主题关联`、`可用在什么项目`。隔三天再比对原文与自己的复述，不要用自己的判断覆盖来源原文。

**验收**：分得清作者观点、自己的转述与尚未验证的新判断；至少有一条来源节点链接。

# 第四章 误区、障碍和方法论（原书 PDF p.119–135）

## 4.1 误区一：记忆力好 ≠ 不需要记录【N】

**练习 16**：把今天已经“自认为记得很牢”的观点写成 Node，3 天后尝试通过关键词而不是记忆定位。验收：仍能找到原位置、记录时间与上下文。

## 4.2 误区二：懂了 ≠ 不值得记录【N】

**练习 17**：为一条熟悉的知识补写“我的实际应用情境”，不是增加更多摘抄。验收：能指出未来再次调用的一个明确场景。

## 4.3 大障碍：日常的想法难以记录【N】

**练习 18**：连续三天用 Journals 或 `Quick add` 捕捉灵感，不要求立即整理。以后再回顾并补充标签/关联。验收：3 条真实灵感，至少 1 条有二次整理痕迹。

## 4.4 两种建设方法（p.130–134）【N】

**原书**：
- **自下而上**：先积累记录，再逐渐发现结构。
- **自上而下**：选择关注主题，有方向地持续收集材料。

**练习 19**：本周各做一次。第一条先在 Journal 自由记录，几天后决定标签；第二条先建立 `[[友谊]]`，带着主题主动新增两则有出处的信息。验收：两种路径都留下可检索记录，且能解释各自局限。

# 附录 B｜常见错误与根因检查

1. `((UUID))` 不是 DB 版正确的块引用方式 → **检查图谱类型，不要改错正文**。
2. 想通过把 `.md` 文件拖进 `pages/` 批量编辑 DB 图谱 → **DB 的真源是 SQLite**；官方提供 File-to-DB 导入流程，而非“直接作为 Markdown 图谱打开”。
3. `{{query...}}` 不执行 → DB 用 `/Query`；高级查询换 `/Advanced Query`，查询结构不同。
4. 所有 `#xxx` 都被当成旧式主题页 → 区分 Tag 与 Page；按 Enter 与 Cmd-Enter 的结果可能不同。
5. 标签 `Extends` 误作父块标签继承 → 前者继承 Tag Properties，后者是块树行为。
6. 只看到 Graph View 就以为 Whiteboard 还在 → 官方明确移除 DB 内置 Whiteboard。
7. 搜索没有返回 → 先创建满足条件的实验数据，再检查筛选是 Tag、文本还是属性。
8. 任务截止时间不显示 → 检查 `Status`、`Deadline`、日期和 Task 过滤，而不是只看文字中的“明天”。
9. 将“重复任务”当手机通知 → 本指南只保证可验证任务和日期重排，不保证推送。
10. 用单次 Markdown 导出备份 DB → **可能丢失 DB 属性与时间元数据**，应使用 SQLite+assets 并恢复抽检。
